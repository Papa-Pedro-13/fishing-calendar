# 01. Обзор продукта

## 1. Что это

**«Календарь рыбалки»** — сервис, который помогает рыболову выбрать **когда, где, на что и
как ловить**. Вместо «погодного приложения» продукт отвечает на прикладной вопрос:
*«стоит ли ехать на этот водоём в этот день, и если да — с какой снастью и наживкой?»*

Продукт объединяет четыре класса данных:

1. **Погода и астрономия** — температура воздуха и воды, давление и его динамика, ветер,
   облачность, осадки, фаза Луны, восход/закат.
2. **Повадки рыб** — видовые профили: сезонные и суточные окна активности, комфортные
   температуры, поведение при изменении давления, нерестовые периоды, типичные места стоянки.
3. **Местоположение** — водоём, его тип (река/озеро/водохранилище/пруд), глубина, течение,
   прозрачность, рельеф, доступность берега.
4. **Отчёты о рыбалке** — что реально ловили в этом месте за последние дни: вид, вес,
   наживка/приманка, снасть, время выхода. Это обратная связь, которая «заземляет»
   теоретические рекомендации.

Пятый, связующий элемент — **ИИ-модель**. Все факторы передаются ей в структурированном
виде, и она формирует **готовый гайд на рыбалку**: оценку дня, лучшие часы, вероятные
виды рыб, наживки и приманки, состав прикормки, параметры поводков и оснастки, тактику
и предупреждения (например, о резкой смене давления или о действующем запрете).

При этом **оценку дня и юридические ограничения считает детерминированный код**, а не
модель: ИИ объясняет и собирает рекомендацию из проверенных фактов, не может отменить
запрет, изменить оценку или придумать цифры. Так гайд остаётся живым по форме и
проверяемым по содержанию — детали в [06](06-recommendations.md).

## 2. Целевая аудитория и задачи

| Сегмент | Задача | Что даёт продукт |
|---|---|---|
| Начинающий рыболов | «Куда и с чем поехать в выходные?» | Готовый план: место, время, снасть, наживка |
| Опытный поплавочник/фидерист | «Будет ли клёв леща после похолодания?» | Объяснимая оценка по факторам, а не «звёзды» |
| Спиннингист | «Где и в какие часы искать щуку/судака?» | Окна активности, приманки, проводка, поводок |
| Локальный эксперт | Поделиться результатом | Отчёты, которые улучшают рекомендации для всех |
| Владелец платника/базы | Привлечь клиентов | Данные о водоёме и прогноз клёва |

Ключевое отличие от «рыболовных календарей» в интернете — **объяснимость и локальность**:
оценка строится из проверяемых факторов (погода, вода, вид, место, свежие отчёты), а не из
общей таблицы «благоприятные дни».

## 3. Пользовательские сценарии (целевые)

### Сценарий A. Планирование поездки
1. Пользователь открывает календарь на 10 дней для своего водоёма.
2. Видит оценки дней и понимает, что лучший — суббота (стабильное давление, тёплая вода,
   растущая Луна, свежие отчёты по судаку).
3. Открывает день: окна активности 5:00–8:00 и 18:00–21:00, рекомендуемая снасть, наживка.
4. Сохраняет место в избранное и включает уведомление об изменении прогноза.

### Сценарий B. «Что взять с собой»
1. Пользователь выбирает вид рыбы, водоём и дату.
2. Получает сгенерированный ИИ гайд: поводок (материал, диаметр, длина), крючок, груз,
   наживка/приманка, состав и норма прикормки, тактика, ограничения по правилам рыболовства
   и объяснение, почему выбраны именно эти снасти и часы.

### Сценарий C. Отчёт после рыбалки
1. Пользователь фиксирует улов: вид, вес, время, точка, снасть, наживка, фото.
2. Отчёт попадает в ленту локации и в агрегат «что работает рядом».
3. Система учитывает подтверждённые отчёты при расчёте рекомендаций (свежесть и
   релевантность взвешиваются).

### Сценарий D. Проверка запретов
1. Пользователь указывает регион и водоём.
2. Система предупреждает о нерестовом запрете, минимальном размере и суточной норме.

## 4. Границы текущей версии (факт)

Сейчас в коде **есть только техническая основа**:

- NestJS-приложение с одним доменным модулем `weather`;
- `GET /api/weather?q=<город|координаты>&days=<1..14>` — прокси к WeatherAPI.com;
- в ответ добавляется `lunarPhase` (фаза и возраст Луны);
- Swagger на `/docs`, CORS, префикс `/api`.

**Нет** ни одного элемента предметной области: ни рыб, ни водоёмов, ни отчётов, ни
рекомендаций, ни базы данных, ни пользователей. То есть продукт как продукт ещё не начат —
реализован один инфраструктурный кирпич. Детали и дефекты — в
[04-implementation-status.md](04-implementation-status.md).

## 5. Границы ближайшего MVP

MVP должен закрывать сценарий A и частично B для **одного региона и 10–15 видов рыб**:

- каталог водоёмов (ручное наполнение, 50–200 точек);
- погодный слой с кэшированием и нормализованной моделью (не «сырой» ответ провайдера);
- профили видов рыб (экспертные знания, версионируемые);
- детерминированный слой фактов и оценок (погода, вода, вид, отчёты, правила) —
  проверенные числа и ограничения, которые передаются ИИ;
- **ИИ-генерация гайда** по всем факторам: структурированный JSON, пост-валидация,
  дисклеймер, кэширование результата;
- шаблонный фолбэк, если LLM недоступна или ответ не прошёл проверку;
- календарь на 7–14 дней с оценкой дня и окнами активности;
- карточка «что взять»: наживка, прикормка, поводок, крючок, тактика;
- отчёты о рыбалке (текст + вид + точка + наживка), лента локации;
- простая авторизация и избранные места;
- предупреждения о региональных запретах (справочник, обновляемый вручную).

Не входит в MVP: обучение собственной модели (на старте используется готовая LLM через
API), ML-ранжирование, соцсеть, платные подписки, интеграция с эхолотами, мобильные
приложения, офлайн-карты.

## 6. Глоссарий

| Термин | Значение |
|---|---|
| **Водоём (WaterBody)** | Река, озеро, водохранилище, пруд, платник; объект с типом и геометрией |
| **Точка (Spot)** | Конкретное место ловли внутри водоёма (координаты + характеристики) |
| **Профиль вида** | Формализованные повадки рыбы: температуры, сезоны, суточная активность, реакция на давление, нерест |
| **Окно активности** | Интервал времени с повышенной вероятностью клёва для вида и условий |
| **Отчёт (CatchReport)** | Пользовательская запись о рыбалке: место, время, вид, снасть, наживка, результат |
| **Рекомендация** | Набор оценок и советов на дату/интервал для вида и точки |
| **Поводок** | Отрезок лески/флюорокарбона/металла между основной леской и крючком/приманкой; важны материал, диаметр, длина |
| **Прикормка** | Смесь для привлечения рыбы к точке; важны состав, фракция, количество, темп закорма |
| **Оснастка** | Монтаж снасти: поплавочная, фидерная, джиговая, волосяная и т.д. |
| **Нерестовый запрет** | Региональный период запрета на ловлю (по видам и водоёмам) |
| **Давление (тренд)** | Абсолютное значение и направление/скорость изменения за 6–24 ч — сильнее влияет на клёв, чем само значение |
| **Фаза Луны** | Освещённость/возраст Луны; в продукте — один из слабых факторов, не «магический» |
| **Факты (facts)** | Детерминированно посчитанный набор входных данных для ИИ: погода по часам, вода, профиль вида, отчёты, правила, оценка и ограничения |
| **ИИ-гайд** | Готовый ответ модели по схеме: сводка, виды, окна, снасть, наживки, прикормка, тактика, предупреждения, объяснение |
| **Промпт-версия** | Идентификатор версии системного промпта и схемы ответа; хранится вместе с рекомендацией для воспроизводимости |
| **Guardrails** | Пост-валидация ответа модели: схема, сверка чисел с фактами, запреты, допустимые виды и снасти |
| **Fallback** | Шаблонная рекомендация без ИИ, если провайдер недоступен, превышен бюджет или ответ не прошёл проверку |
| **inputsHash** | Хеш канонического набора фактов + промпт-версии + модели; ключ кэша и способ воспроизвести гайд |
